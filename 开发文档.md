## 一、系统概述

### 1.1 项目定位

基于 AI Agent 的企业运营智能诊断系统，面向电商行业。系统为 **多租户 SaaS 公共服务**，服务生态内所有企业。通过 LangGraph 编排多步诊断流程，通过 MCP (Model Context Protocol) 标准协议 **动态接入各企业的业务系统实例**，实现：

**一键诊断 → 方案生成 → 执行推送 → 效果追踪 → 复盘沉淀** 的全闭环。

### 1.1.1 多租户 SaaS 模型

```
诊断系统（公共服务，单实例部署）
    │
    ├── 诊断任务A ──► 企业A 的 API (https://ent-a.wlwq.com/api)
    ├── 诊断任务B ──► 企业B 的 API (https://ent-b.wlwq.com/api)
    ├── 诊断任务C ──► 企业C 的 API (https://ent-c.wlwq.com/api)
    └── ...
```

**核心设计约束**：
- 诊断系统是一个公共服务，部署一套，服务所有企业
- 每个诊断任务绑定一个具体企业（`tenant_id`），调用该企业对应的业务系统 API
- 不同企业可能部署在不同服务实例上（独立部署/集群），API 地址不同
- 企业间数据严格隔离，每次 MCP tool 调用都携带租户上下文
- 行业基准数据是跨企业的汇总数据，由平台中台统一提供

### 1.2 核心架构选型

| 组件 | 选型 | 职责 |
|------|------|------|
| Agent编排 | LangGraph (Python) | 状态管理、多节点流转、中断恢复、条件路由 |
| 业务接入 | MCP Server (Python, SSE) | 封装业务系统API，提供标准化Tool供Agent调用 |
| LLM | 通义千问 qwen-max / GPT-4o | 根因分析、方案生成、复盘归因 |
| 进度推送 | WebSocket (FastAPI) | 实时推送诊断过程中间状态给调用方 |
| 状态持久化 | PostgreSQL (LangGraph Checkpointer) | 存储Graph State，支持中断恢复 |
| 缓存 | Redis | 行业基准数据缓存、诊断结果缓存 |

**关键链路说明**：
- 诊断系统是 **多租户 SaaS 公共服务**，单实例部署，服务所有企业
- MCP Server 是 **Python 实现**，通过 SSE 方式暴露 Tool
- 每次 MCP Tool 调用都携带 `tenant_id`，由 **租户路由层** 解析出该企业的 API 地址和鉴权凭证

- 行业基准数据通过 **平台中台** 统一提供，不属于某个企业
- LangGraph 作为 MCP Client 消费这些 Tool

## 二、MCP Server 设计

### 2.1 总体设计原则

1. 每个 MCP Server 对应一个业务域，单一职责
2. Python 实现，使用 `mcp` SDK，传输方式为 SSE (HTTP)
3. 内部通过 `httpx` 异步调用现有业务系统 REST API
4. 不直连 MySQL，所有数据通过业务系统 API 获取
5. 对业务系统返回的原始数据做聚合/计算后返回给 Agent
6. **每个 MCP Tool 调用必须携带 `tenant_id`**，由租户路由层解析到目标企业 API
7. 行业基准数据通过平台中台获取，与企业 API 分开路由

### 2.2 租户路由层 (TenantRouter)

诊断系统作为 SaaS 公共服务，需要根据 `tenant_id` 动态路由到不同企业的业务系统。这是所有 MCP Server 共享的基础设施层。

#### 租户注册表

诊断系统维护一张 **租户注册表**（存储在 PostgreSQL，Redis 缓存）：

```sql
-- 存储在诊断系统自身的 PostgreSQL 中（ops_brain 库）
CREATE TABLE tenant_registry (
    tenant_id       VARCHAR(32) PRIMARY KEY,           -- 租户ID（通常=store_id或企业编码）
    tenant_name     VARCHAR(128) NOT NULL,              -- 企业名称
    api_base_url    VARCHAR(256) NOT NULL,              -- 企业业务系统API地址
                                                        -- 如 https://ent-a.wlwq.com/api
    auth_type       VARCHAR(16) DEFAULT 'token',        -- 鉴权方式: token / oauth2 / hmac
    auth_credential TEXT NOT NULL,                       -- 鉴权凭证（加密存储）
                                                        -- token模式: 直接存token
                                                        -- oauth2模式: 存 client_id:client_secret
    industry_code   VARCHAR(32),                         -- 所属行业编码（用于匹配行业基准）
    status          SMALLINT DEFAULT 1,                  -- 0停用 1正常
    config          JSONB DEFAULT '{}',                  -- 企业级个性化配置
                                                        -- 如自定义诊断维度权重、额外指标等
    created_at      TIMESTAMP DEFAULT NOW(),
    updated_at      TIMESTAMP DEFAULT NOW()
);

-- 平台中台作为特殊租户，industry_code=NULL
INSERT INTO tenant_registry (tenant_id, tenant_name, api_base_url, auth_type, auth_credential)
VALUES ('__platform__', '平台中台', 'https://platform-center.wlwq.com/api', 'token', 'encrypted_token');
```

#### TenantRouter 实现

```python
import httpx
from dataclasses import dataclass

@dataclass
class TenantContext:
    tenant_id: str
    tenant_name: str
    api_base_url: str       # 该企业的业务系统地址
    auth_headers: dict      # 已组装好的鉴权请求头
    industry_code: str | None
    config: dict            # 企业个性化配置

class TenantRouter:
    """
    租户路由器 — 所有MCP Server共享。
    根据 tenant_id 解析出目标企业的 API 地址和鉴权信息。
    """
    
    def __init__(self, pg_pool, redis_client):
        self.pg_pool = pg_pool
        self.redis = redis_client
        self._http_clients: dict[str, httpx.AsyncClient] = {}
    
    async def resolve(self, tenant_id: str) -> TenantContext:
        """
        解析租户上下文。优先从 Redis 缓存读取，未命中查 PostgreSQL。
        """
        cache_key = f"tenant:{tenant_id}"
        cached = await self.redis.hgetall(cache_key)
        if cached:
            return TenantContext(**cached)
        
        async with self.pg_pool.connection() as conn:
            row = await conn.fetchrow(
                "SELECT * FROM tenant_registry WHERE tenant_id=$1 AND status=1",
                tenant_id
            )
        if not row:
            raise TenantNotFoundError(f"租户 {tenant_id} 不存在或已停用")
        
        ctx = TenantContext(
            tenant_id=row["tenant_id"],
            tenant_name=row["tenant_name"],
            api_base_url=row["api_base_url"],
            auth_headers=self._build_auth_headers(row["auth_type"], row["auth_credential"]),
            industry_code=row["industry_code"],
            config=row["config"] or {},
        )
        
        # 缓存到 Redis，TTL 10分钟
        await self.redis.hset(cache_key, mapping=ctx.__dict__)
        await self.redis.expire(cache_key, 600)
        return ctx
    
    async def get_client(self, tenant_id: str) -> httpx.AsyncClient:
        """
        获取面向指定租户的 HTTP Client（连接池复用）。
        """
        if tenant_id not in self._http_clients:
            ctx = await self.resolve(tenant_id)
            self._http_clients[tenant_id] = httpx.AsyncClient(
                base_url=ctx.api_base_url,
                headers=ctx.auth_headers,
                timeout=30.0,
            )
        return self._http_clients[tenant_id]
    
    async def get_platform_client(self) -> httpx.AsyncClient:
        """获取平台中台的 HTTP Client（行业基准等公共数据）。"""
        return await self.get_client("__platform__")
    
    def _build_auth_headers(self, auth_type: str, credential: str) -> dict:
        decrypted = decrypt(credential)  # AES解密
        if auth_type == "token":
            return {"Authorization": f"Bearer {decrypted}"}
        elif auth_type == "hmac":
            return {"X-Service-Signature": compute_hmac(decrypted)}
        return {}
```

### 2.3 MCP Server 清单

共需 **5 个 MCP Server**：

| # | Server 名称 | 职责 | 读/写 |
|---|------------|------|-------|
| 1 | `metrics-server` | 运营指标采集与计算 | 读 |
| 2 | `crm-server` | CRM客户数据、企业画像 | 读 |
| 3 | `benchmark-server` | 行业基准数据管理 | 读+写 |
| 4 | `task-server` | 向业务系统推送任务/方案 | 写 |
| 5 | `notify-server` | 向业务系统推送消息通知 | 写 |

**为什么拆成5个而不是更多/更少？**

- `metrics-server` 最重，4个诊断维度的指标计算全在里面，但它们共享相同的调用模式（查询+聚合），放在一起便于统一管理数据时间窗口
- `crm-server` 独立出来是因为客户数据不仅用于诊断采集，方案生成阶段也需要客户画像做个性化适配
- `benchmark-server` 独立是因为行业基准数据有自己的更新周期（月度），且可以缓存
- `task-server` 和 `notify-server` 都是写操作，但推送的目标不同（任务系统 vs 消息系统），分开可以独立部署和限流

#### 内部实现模式

每个 tool 内部的通用调用模式 — 通过 TenantRouter 动态路由：

```python
import asyncio
from mcp_servers.tenant_router import TenantRouter

class MetricsServer:
    def __init__(self, router: TenantRouter):
        self.router = router  # 共享的租户路由器

    async def get_crm_indicators(self, tenant_id, store_id, start_date, end_date):
        # 1. 通过 TenantRouter 获取该企业的 HTTP Client
        client = await self.router.get_client(tenant_id)
        # client 已绑定: base_url=该企业API地址, headers=该企业鉴权Token
        
        # 2. 并发调用该企业的多个业务API
        clients_resp, contracts_resp, follows_resp = await asyncio.gather(
            client.get("/client-record/statistics", params={"storeId": store_id, "startDate": start_date, "endDate": end_date}),
            client.get("/sales-contract/statistics", params={"storeId": store_id, "startDate": start_date, "endDate": end_date}),
            client.get("/examine-initiate/follow-stats", params={"storeId": store_id, "startDate": start_date, "endDate": end_date}),
        )
        
        # 3. 聚合计算指标
        total_clients = clients_resp.json()["data"]["total"]
        signed_clients = contracts_resp.json()["data"]["signedCount"]
        lead_conversion_rate = (signed_clients / total_clients * 100) if total_clients > 0 else 0
        
        # 4. 返回结构化结果 (lead_conversion_rate, response_time_avg, follow_up_count)
        return {
            "tenant_id": tenant_id,
            "dimension": "crm",
            "period": f"{start_date} ~ {end_date}",
            "indicators": {
                "lead_conversion_rate": {
                    "value": round(lead_conversion_rate, 2),
                    "unit": "%",
                    "direction": "higher_is_better",
                    "raw_data": {"total_clients": total_clients, "signed_clients": signed_clients}
                },
                # ... response_time_avg, follow_up_count
            }
        }

    async def get_marketing_indicators(self, tenant_id, store_id, start_date, end_date):
        client = await self.router.get_client(tenant_id)  # 同样先路由
        # ... 调用该企业的营销相关API
```

```python
from typing import TypedDict, Annotated, Literal

class DiagnosisState(TypedDict):
    """诊断流程全局状态"""

    tenant_id: str             # 租户ID — 决定调用哪个企业的API
    store_id: str              # 店铺/企业ID

    triggered_by: str | None   # 触发人user_id

    marketing_indicators: dict | None
```

### 3.2 节点与边

```python
from langgraph.graph import StateGraph, END
from langgraph.checkpoint.postgres.aio import AsyncPostgresSaver

graph = StateGraph(DiagnosisState)

# ---- 注册节点 ----
graph.add_node("collect_data", collect_data_node)
graph.add_node("diagnose", diagnose_node)
graph.add_node("generate_solutions", generate_solutions_node)
graph.add_node("wait_adoption", wait_adoption_node)
graph.add_node("execute_plans", execute_plans_node)
graph.add_node("track_effects", track_effects_node)

# ---- 入口 ----
graph.set_entry_point("collect_data")

# ---- 边 ----
graph.add_edge("collect_data", "diagnose")
graph.add_edge("diagnose", "generate_solutions")

# 诊断完成后的路由: 手动触发 → 等待采纳; 自动触发 → 仅通知不执行
def route_after_solutions(state: DiagnosisState) -> str:
    if not state.get("anomalies"):
        return END  # 无异常，流程结束
    if state["trigger_type"] == "scheduled":
        return END  # 周度自动诊断只生成报告，不进入执行
    return "wait_adoption"

graph.add_conditional_edges("generate_solutions", route_after_solutions,
    {"wait_adoption": "wait_adoption", END: END})

# 用户采纳后的路由
def route_after_adoption(state: DiagnosisState) -> str:
    if state.get("adopted_plan_ids"):
        return "execute_plans"
    return END  # 用户未采纳

graph.add_conditional_edges("wait_adoption", route_after_adoption,
    {"execute_plans": "execute_plans", END: END})

graph.add_edge("execute_plans", "track_effects")
graph.add_edge("track_effects", END)

# ---- 编译 ----
checkpointer = AsyncPostgresSaver.from_conn_string(POSTGRES_URI)
interrupts = ["wait_adoption"]
if settings.effect_track_delay_days > 0:
    interrupts.append("track_effects")  # 延迟复盘：执行完后中断，由调度器到期恢复
app = graph.compile(
    checkpointer=checkpointer,
    interrupt_before=interrupts
)
```

#### diagnose_node — 诊断分析

```python
async def diagnose_node(state: DiagnosisState) -> dict:
    """
    1. 规则计算: 各维度得分、异常指标识别
    2. LLM调用: 对异常指标做根因分析
    3. 生成诊断报告
    4. 推送通知
    """
    emit_progress(state, "正在计算运营健康度...")

    # ---- 步骤1: 规则计算 ----
    dimension_scores = {}
    anomalies = []

    for dim_name, indicators, weight in [
        ("crm", state["crm_indicators"], 0.25),
        ("marketing", state["marketing_indicators"], 0.30),
        ("retention", state["retention_indicators"], 0.25),
        ("efficiency", state["efficiency_indicators"], 0.20),
    ]:
        score, dim_anomalies, ind_scores = calculate_dimension_score(
            indicators=indicators,
            benchmarks=state["benchmarks"],
            dimension=dim_name
        )
        dimension_scores[dim_name] = {"score": score, "weight": weight}
        anomalies.extend(dim_anomalies)

    health_score = sum(d["score"] * d["weight"] for d in dimension_scores.values())
    
    emit_progress(state, f"健康度评分: {health_score:.1f}分, 发现 {len(anomalies)} 项异常指标")

    # ---- 步骤2: LLM根因分析 ----
    if anomalies:
        emit_progress(state, "AI正在分析异常根因...")
        root_causes = await llm_root_cause_analysis(
            store_profile=state["store_profile"],
            anomalies=anomalies,
            all_indicators={
                "crm": state["crm_indicators"],
                "marketing": state["marketing_indicators"],
                "retention": state["retention_indicators"],
                "efficiency": state["efficiency_indicators"],
            }
        )
    else:
        root_causes = []

    # ---- 步骤3: 生成诊断报告 ----
    diagnosis_report = build_diagnosis_report(
        store_profile=state["store_profile"],
        health_score=health_score,
        dimension_scores=dimension_scores,
        anomalies=anomalies,
        root_causes=root_causes
    )

    # ---- 步骤4: 推送通知 ----
    emit_progress(state, "诊断完成，正在推送报告...")
    await mcp_call("notify-server", "send_diagnosis_report_notification", {
        "store_id": state["store_id"],
        "admin_account_ids": get_admin_accounts(state["store_profile"]),
        "report_summary": {
            "health_score": health_score,
            "anomaly_count": len(anomalies),
            "top_anomaly": anomalies[0]["description"] if anomalies else None,
        }
    })

    return {
        "health_score": health_score,
        "dimension_scores": dimension_scores,
        "anomalies": anomalies,
        "root_causes": root_causes,
        "diagnosis_report": diagnosis_report,
    }
```

```python
async def generate_solutions_node(state: DiagnosisState) -> dict:
    """
    基于异常指标 + 模板库 + LLM 生成优化方案
    """
    if not state.get("anomalies"):
        return {"solution_plans": []}

    emit_progress(state, "正在匹配优化方案模板...")

    industry_code = state["store_profile"]["industry_code"]

    # 1. 从模板库检索相关模板
    templates = await mcp_call("benchmark-server", "get_industry_benchmark", {
        "industry_code": industry_code,
        "indicator_codes": [a["indicator_code"] for a in state["anomalies"]]
    })

    # 2. LLM生成个性化方案
    emit_progress(state, "AI正在生成个性化优化方案...")
    
    plans = await llm_generate_solutions(
        store_profile=state["store_profile"],
        anomalies=state["anomalies"],
        root_causes=state["root_causes"],
        templates=templates,
        indicators={
            "crm": state["crm_indicators"],
            "marketing": state["marketing_indicators"],
            "retention": state["retention_indicators"],
            "efficiency": state["efficiency_indicators"],
        }
    )

    # 3. 计算优先级排序
    for plan in plans:
        plan["priority_score"] = (
            plan["expected_roi"] * 0.6 +
            (10 - plan["difficulty_score"]) * 0.2 +
            plan["urgency_score"] * 0.2
        )
    plans.sort(key=lambda p: p["priority_score"], reverse=True)

    emit_progress(state, f"已生成 {len(plans)} 个优化方案，等待采纳")

    # 4. 推送待采纳通知
    await mcp_call("notify-server", "send_plan_adoption_request", {
        "store_id": state["store_id"],
        "admin_account_ids": get_admin_accounts(state["store_profile"]),
        "plans_summary": [{"name": p["plan_name"], "priority": p["priority_level"]} for p in plans]
    })

    return {"solution_plans": plans}
```

#### execute_plans_node — 执行推送

```python
async def execute_plans_node(state: DiagnosisState) -> dict:
    """
    将采纳的方案转为执行任务，推送至业务系统
    """
    adopted_ids = state.get("adopted_plan_ids", [])
    adopted_plans = [p for p in state["solution_plans"] if p["plan_id"] in adopted_ids]
    
    all_tasks = []
    for plan in adopted_plans:
        emit_progress(state, f"正在创建方案「{plan['plan_name']}」的执行任务...")
        
        # 匹配负责人
        dept_info = await mcp_call("crm-server", "get_dept_structure", {
            "store_id": state["store_id"]
        })
        
        tasks = build_execution_tasks(plan, dept_info)
        
        # 推送任务到业务系统
        result = await mcp_call("task-server", "create_execution_tasks", {
            "store_id": state["store_id"],
            "plan_id": plan["plan_id"],
            "tasks": tasks
        })
        
        all_tasks.extend(result["created_tasks"])

        # 如果方案包含营销动作，直接创建
        for action in plan.get("auto_actions", []):
            if action["type"] == "coupon_campaign":
                await mcp_call("task-server", "create_coupon_campaign", {
                    "store_id": state["store_id"],
                    "campaign_config": action["config"]
                })
                emit_progress(state, f"已自动创建优惠券活动: {action['config']['coupon_name']}")

    emit_progress(state, f"共创建 {len(all_tasks)} 个执行任务")

    # 延迟复盘调度：写入 ai_pending_review，由 effect_review_checker 到期触发
    delay_days = get_settings().effect_track_delay_days
    if delay_days > 0:
        due_date = (datetime.now() + timedelta(days=delay_days)).date()
        await save_pending_review(thread_id, tenant_id, store_id, due_date)
        emit_progress(state, f"效果追踪已调度，将于 {due_date} 自动执行复盘")
    
    return {"exec_tasks": all_tasks}
```

#### 延迟复盘机制

方案执行后不再立即进行效果追踪，而是延迟 `EFFECT_TRACK_DELAY_DAYS`（默认 7 天）后由定时任务自动触发：

1. `execute_plans_node` 执行完毕时，写入 `ai_pending_review` 表（`review_due_date = 今天 + delay_days`）
2. Graph 在 `track_effects` 节点前中断（`interrupt_before`）
3. 每日 3:00 `effect_review_checker` 扫描到期记录，恢复 Graph 继续执行 `track_effects`
4. 复盘完成后标记 `ai_pending_review.status = 'completed'`

配置项 `EFFECT_TRACK_DELAY_DAYS=0` 可关闭延迟，恢复立即执行。

#### track_effects_node — 效果追踪


## 四、WebSocket 进度推送

### 4.1 设计方案

LangGraph 本身不直接支持 WebSocket，但可以通过 **stream 模式 + FastAPI WebSocket** 实现实时进度推送。

核心思路：
1. LangGraph 的 `astream_events` 方法可以流式输出每个节点的执行事件
2. 在每个节点内部通过 `state["progress_messages"]` 记录进度消息
3. FastAPI WebSocket 端点消费 stream 并推送给客户端

### 4.2 实现方式

```python
# ============================================================
# FastAPI 服务层
# ============================================================
from fastapi import FastAPI, WebSocket, WebSocketDisconnect
from fastapi.responses import JSONResponse
import json

app_api = FastAPI()

# ---- WebSocket 连接管理 ----
class ConnectionManager:
    def __init__(self):
        self.active: dict[str, WebSocket] = {}  # thread_id → ws
    
    async def connect(self, thread_id: str, ws: WebSocket):
        await ws.accept()
        self.active[thread_id] = ws
    
    def disconnect(self, thread_id: str):
        self.active.pop(thread_id, None)
    
    async def send_progress(self, thread_id: str, message: dict):
        ws = self.active.get(thread_id)
        if ws:
            await ws.send_json(message)

manager = ConnectionManager()


# ---- WebSocket 端点: 实时诊断进度 ----
@app_api.websocket("/api/v1/ws/diagnosis/{thread_id}")
async def ws_diagnosis(websocket: WebSocket, thread_id: str):
    await manager.connect(thread_id, websocket)
    try:
        while True:
            # 保持连接，接收客户端消息（如采纳方案）
            data = await websocket.receive_json()
            
            if data.get("action") == "adopt_plans":
                # 用户采纳方案 → resume LangGraph
                await resume_with_adoption(thread_id, data["plan_ids"])
            
    except WebSocketDisconnect:
        manager.disconnect(thread_id)


# ---- HTTP 触发诊断 ----
@app_api.post("/api/v1/diagnosis/start")
async def start_diagnosis(request: DiagnosisRequest):
    """
    request body: { tenant_id, store_id, trigger_type }
    tenant_id 标识目标企业，决定后续所有MCP调用路由到哪个企业的API
    """
    thread_id = generate_thread_id()
    
    # 后台异步运行LangGraph，通过stream推送进度
    asyncio.create_task(
        run_diagnosis_with_stream(thread_id, request.tenant_id, request.store_id, request.trigger_type)
    )
    
    return {"thread_id": thread_id, "ws_url": f"/api/v1/ws/diagnosis/{thread_id}"}


# ---- 核心: 流式运行LangGraph并推送 ----
async def run_diagnosis_with_stream(thread_id: str, tenant_id: str, store_id: str, trigger_type: str):
    config = {"configurable": {"thread_id": thread_id}}
    initial_state = {
        "tenant_id": tenant_id,    # 租户ID贯穿整个流程
        "store_id": store_id,
        "trigger_type": trigger_type,
        "progress_messages": []
    }
    
    async for event in app.astream_events(initial_state, config=config, version="v2"):
        kind = event["event"]
        
        if kind == "on_chain_start":
            node_name = event.get("name", "")
            await manager.send_progress(thread_id, {
                "type": "node_start",
                "node": node_name,
                "timestamp": datetime.now().isoformat()
            })
        
        elif kind == "on_chain_end":
            node_name = event.get("name", "")
            output = event.get("data", {}).get("output", {})
            
            # 提取该节点产生的进度消息
            if "progress_messages" in output:
                for msg in output["progress_messages"]:
                    await manager.send_progress(thread_id, {
                        "type": "progress",
                        "message": msg["content"],
                        "timestamp": msg["timestamp"]
                    })
            
            # 节点完成通知
            await manager.send_progress(thread_id, {
                "type": "node_complete",
                "node": node_name,
                "timestamp": datetime.now().isoformat()
            })
            
            # 特定节点完成时推送关键数据
            if node_name == "diagnose" and "health_score" in output:
                await manager.send_progress(thread_id, {
                    "type": "diagnosis_result",
                    "health_score": output["health_score"],
                    "anomaly_count": len(output.get("anomalies", [])),
                    "dimension_scores": output.get("dimension_scores")
                })
            
            if node_name == "generate_solutions" and "solution_plans" in output:
                await manager.send_progress(thread_id, {
                    "type": "solutions_ready",
                    "plans": output["solution_plans"]  # 前端展示方案列表
                })
        
        elif kind == "on_chain_stream":
            # interrupt 发生时
            pass
    
    # 流程结束或中断
    state = await app.aget_state(config)
    if state.next:  # 有下一步 = 被interrupt了(等待采纳)
        await manager.send_progress(thread_id, {
            "type": "waiting_adoption",
            "message": "方案已生成，请选择需要采纳的方案"
        })
    else:
        await manager.send_progress(thread_id, {
            "type": "completed",
            "message": "诊断流程已完成"
        })


# ---- Resume: 用户采纳方案后继续执行 ----
async def resume_with_adoption(thread_id: str, plan_ids: list[str]):
    config = {"configurable": {"thread_id": thread_id}}
    
    # 更新state中的adopted_plan_ids
    await app.aupdate_state(config, {"adopted_plan_ids": plan_ids})
    
    # 继续流式运行
    async for event in app.astream_events(None, config=config, version="v2"):
        kind = event["event"]
        if kind == "on_chain_end":
            node_name = event.get("name", "")
            output = event.get("data", {}).get("output", {})
            
            await manager.send_progress(thread_id, {
                "type": "node_complete",
                "node": node_name,
                "timestamp": datetime.now().isoformat()
            })
    
    await manager.send_progress(thread_id, {
        "type": "completed",
        "message": "方案执行任务已全部创建"
    })
```

### 5.2 诊断系统 → 业务系统：写操作（通过 MCP task/notify server）

这是核心问题 — 诊断系统会向业务系统推送以下任务和消息：

#### 5.2.1 消息通知类（notify-server）

| # | 通知类型 | 触发时机 | 目标 | 对应业务表 |
|---|---------|---------|------|-----------|
| 1 | 诊断报告完成通知 | 诊断阶段完成后 | 企业管理员 | message_remind |
| 2 | 方案待采纳通知 | 方案生成后 | 企业管理员 | message_remind |
| 3 | 任务分配通知 | 执行任务创建后 | 任务负责人 | message_remind |
| 4 | 任务即将到期提醒 | 定时检查(距截止1天) | 任务负责人 | message_remind |
| 5 | 任务超期提醒 | 定时检查(超过截止日) | 任务负责人+管理员 | message_remind |
| 6 | 复盘报告完成通知 | 复盘阶段完成后 | 企业管理员 | message_remind |
| 7 | 周度诊断自动推送 | 每周一凌晨 | 企业管理员 | message_remind |

#### 5.2.2 任务创建类（task-server）

| # | 任务类型 | 触发时机 | 说明 | 对应业务操作 |
|---|---------|---------|------|------------|
| 1 | 执行任务 | 用户采纳方案后 | 分解方案步骤为具体任务，分配负责人和截止日期 | 写入新表 exec_task 或复用 examine_initiate |
| 2 | 审批流程 | 方案需审批时 | 发起OA审批流程 | 写入 examine_initiate |
| 3 | 优惠券活动 | 营销类方案执行时 | 自动创建优惠券并定向发放给目标客户群 | 写入 coupon + account_coupon |
| 4 | 秒杀活动 | 营销类方案执行时 | 自动创建限时秒杀活动 | 写入 seckill_apply |

#### 5.2.3 各异常指标对应的具体推送动作

| 异常指标 | 推送任务类型 | 具体动作 |
|---------|------------|---------|
| 线索转化率低 | 执行任务 | 创建"线索跟进优化"任务 → 分配给销售主管，要求24h内首次跟进 |
| 优惠券核销率低 | 执行任务 + 消息 | 创建"优惠券策略调整"任务 + 向目标客户推送即将过期提醒 |
| 复购率低 | 优惠券活动 | 自动创建老客户回馈优惠券，定向发放给90天未复购客户 |
| 退款率高 | 执行任务 | 创建"退款原因分析与商品质量改进"任务 → 分配给运营 |
| 好评率低 | 执行任务 | 创建"售后服务优化"任务 + "差评客户回访"任务 |
| 发货时效差 | 执行任务 | 创建"仓储发货流程优化"任务 → 分配给仓储负责人 |
| 流失率高 | 优惠券活动 + 消息 | 自动创建挽回优惠券 + 推送关怀消息给流失风险客户 |
