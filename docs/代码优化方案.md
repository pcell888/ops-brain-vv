# 代码优化方案

> 轻量化架构优先，小项目不搞过度抽象，但职责清晰、分层清晰是必要约束。

---

## 一、问题定位

经过代码 Review，核心问题集中在这几类：

| 类别 | 问题数 | 影响 |
|------|--------|------|
| **重复代码** | 15 处模式重复，约 600 行 | 修改一处漏改其他，bug 隐患 |
| **目录膨胀** | `core/` 塞了 20+ 文件 | 职责不清，新人难定位 |
| **进度推送多套机制** | 3 层交织（State / Redis / WS） | 消息丢失、顺序错乱 |
| **全局状态** | 8+ 处模块级变量 | 测试难、并发风险 |

---

## 二、优化原则

1. **接口契约不变**：不改变任何 API 路由、请求参数、响应结构
2. **轻量化架构**：小项目不用 DDD / 六边形这些重型架构，但分层清晰、职责清晰是必要约束
3. **渐进式重构**：按优先级分阶段执行，每阶段可独立验证
4. **零风险先行**：P0 纯机械重构，只移不删，只增不改

```python
"""阶段定义与进度计算 — 全流程单一信源。"""

from __future__ import annotations

PHASE_DIAGNOSIS = "diagnosis"
PHASE_ADOPTION = "adoption"
PHASE_EXECUTION = "execution"
PHASE_TRACKING = "tracking"
PHASE_COMPLETED = "completed"

PHASE_NAME = {
    PHASE_DIAGNOSIS: "诊断",
    PHASE_ADOPTION: "采纳",
    PHASE_EXECUTION: "执行",
    PHASE_TRACKING: "追踪",
    PHASE_COMPLETED: "已完成",
}

# (min_percent, max_percent) 区间
PHASE_OVERALL_RANGE = {
    PHASE_DIAGNOSIS: (0, 60),
    PHASE_ADOPTION: (60, 75),
    PHASE_EXECUTION: (75, 90),
    PHASE_TRACKING: (90, 99),
    PHASE_COMPLETED: (100, 100),
}

WORKFLOW_NODES = frozenset({
    "collect_data", "diagnose", "generate_solutions",
    "wait_adoption", "execute_plans", "track_effects",
})

def calc_overall_progress(phase: str, phase_progress: int) -> int:
    p = max(0, min(100, int(phase_progress)))
    lo, hi = PHASE_OVERALL_RANGE.get(phase, (0, 100))
    if lo == hi:
        return lo
    return int(round(lo + (hi - lo) * (p / 100.0)))

def infer_next_phase(phase: str, status: str) -> str | None:
    if status in ("failed", "not_found"):
        return None
    order = [PHASE_DIAGNOSIS, PHASE_ADOPTION, PHASE_EXECUTION, PHASE_TRACKING, PHASE_COMPLETED]
    try:
        idx = order.index(phase)
        return order[idx + 1] if idx + 1 < len(order) else None
    except ValueError:
        return None
```

**改动：** `diagnosis_service.py`、`solution_service.py`、`review_service.py`、`diagnosis_stream_runner.py` 中的重复定义改为 import。

#### 4.1.2 新建 `src/core/progress.py` — 统一进度提取

**新增文件：`src/core/progress.py`**

```python
"""进度消息提取工具 — 统一 cache + LangGraph State 的进度读取。"""

from __future__ import annotations

from src.runtime.graph_app import get_graph_app
from src.runtime.progress_store import progress_cache

async def get_latest_progress(thread_id: str) -> tuple[str, int]:
    """返回 (message, percent)，优先 cache，其次 state.messages。"""
    cached = await progress_cache.aget(thread_id)
    if cached:
        msg = str(cached.get("message", "") or "").strip()
        try:
            pct = int(float(cached.get("percent", 0) or 0))
        except (TypeError, ValueError):
            pct = 0
        return msg, pct

    try:
        app = await get_graph_app()
        state = await app.aget_state({"configurable": {"thread_id": thread_id}})
        values = state.values if state and state.values else {}
        msgs = values.get("progress_messages") or []
        if msgs:
            last = msgs[-1] if isinstance(msgs[-1], dict) else {}
            msg = str(last.get("content", "") or "").strip()
            try:
                pct = int(float(last.get("percent", 0) or 0))
            except (TypeError, ValueError):
                pct = 0
            return msg, pct
    except Exception:
        pass
    return "", 0


async def is_thread_running(thread_id: str) -> bool:
    """统一判断 thread 是否在运行。"""
    from src.runtime.running_tasks import running_tasks
    task = running_tasks.get(thread_id)
    return (task is not None and not task.done()) or await running_tasks.is_running(thread_id)
```

#### 4.1.3 新建 `src/core/json_utils.py` — 统一 JSON 工具

消除 2 处 `_strip_json_fence` 重复。合并 `llm_caller.py` 和 `tools.py` 中的实现。

```python
"""JSON 解析工具。"""
from __future__ import annotations

def strip_json_fence(text: str) -> str:
    body = text.strip()
    if body.startswith("```"):
        body = body.split("\n", 1)[1].rsplit("```", 1)[0].strip()
    return body

def parse_json_fence(text: str) -> dict | None:
    import json
    body = strip_json_fence(text)
    try:
        parsed = json.loads(body)
        return parsed if isinstance(parsed, dict) else None
    except json.JSONDecodeError:
        return None
```

## 七、潜在改进点与注意事项

### 7.1 图恢复逻辑统一建议补充细节

当前方案提到"合并 3 处图恢复逻辑为 `runtime/task_runner.py`"，建议在执行前补充以下分析：

1. **场景差异梳理**：
   - `diagnosis_stream_runner.py`：完整的诊断流程，从初始状态开始
   - `solution_service.py::resume_after_adoption`：从 `wait_adoption` 节点恢复，继续执行 `execute_plans`
   - `review_service.py::resume_track_effects`：从 `track_effects` 节点开始

2. **统一函数设计建议**：
   ```python
   async def run_graph_with_progress(
       thread_id: str,
       config: dict,
       *,
       initial_state: dict | None = None,  # 初始状态（首次执行）
       skip_nodes: set[str] | None = None,
       progress_stage: str = "diagnosis",
       on_node_complete: Callable | None = None,
       allowed_nodes: set[str] | None = None,  # 允许执行的节点（限制执行范围）
   ) -> None:
       """统一的图执行 + 进度推送入口。"""
   ```

### 7.2 Repo 函数统一建议先梳理依赖关系

在执行 P2-2 阶段前，建议先：
